## Learnings

- **Three premises in the source proposal were false and are corrected in the
  landed documents.** (a) The repository has no notebook policy — no `*.ipynb`
  ignore rule, no `nbstripout` filter, and 18 tracked notebooks *with outputs*
  in analysis plus 1 in the parent. (b) `make observations|fit|verify|review` is
  not a general four-stage analysis interface; all four are `.PHONY` wrappers
  around `scripts/run_dualband_burst_model.py --stage`, prerequisite-chained,
  run in a separate `.venv-dualband` via `UV_PROJECT_ENVIRONMENT` with
  `uv run --locked --no-sync --group dualband`, and only `observations` guards
  `EVENT`. (c) Adding `ipykernel` is gated by authority-10.
- **Parent pointers to analysis documents are incoherent without a pin
  advance.** The parent sees only the commit its gitlink selects. This killed
  U8 and U9 and is why parent work must be one integration pull request that
  advances the pin *and* adds the pointers. The same defect applies to any
  end-to-end check run as `make -C analysis …` from the parent: it exercises the
  pinned commit, not the newly merged code.
- **`git check-ignore` consults the index.** An already-tracked path reports as
  not-ignored regardless of the patterns, so a grandfathering test written
  without `--no-index` passes even with the negation deleted. Reproduced
  empirically in a scratch repository.
- **`uv` leaves dependency-group packages resident in the shared `.venv`.** U3's
  smoke test appeared to pass under `--group test` alone; it was environment
  persistence, not a design flaw (the round-trip is `@pytest.mark.slow` with
  `importorskip` guards, and `make test`'s marker filter deselects it — 2 of 3
  collected). Consequence: locally the skip guard is never exercised once
  notebook packages land, so `make test` *looks* like it covers the kernel.
  Real admission evidence comes from `make test-notebook`.
- **A `--user` kernelspec is wrong for a worktree workflow.** It embeds the
  absolute interpreter path of whichever checkout registered it and breaks
  silently when that worktree is removed. The surface is therefore kernel-only:
  editor selects the worktree interpreter directly, session records the exact
  path, no permanent kernelspec.
- **`verify-gate --paths` is `nargs="+"`, not a repeatable flag.** Passing
  `--paths a --paths b` silently records only `b`. One flag, several values.
- **The `code-review` skill is `disable-model-invocation`** and refuses
  Skill-tool calls from agents. Workers should use the `code-reviewer` agent or
  deterministic checks and record which route was used.
- **Worktree placement was wrong.** The eight analysis worktrees were created
  under `~/Developer/scratch/worktrees/`; the current protocol is
  `<repo>/.grit/worktrees/`. They were left in place rather than relocated
  mid-pause.
